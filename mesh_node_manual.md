# MeshNode Application Manual

Welcome to the **MeshNode** comprehensive guide. This manual provides detailed instructions on how to use the MeshNode application across both **Windows** and **iOS** platforms.

MeshNode is a decentralized, peer-to-peer AI inference application. It utilizes a Ring All-Reduce network topology and libp2p discovery to connect multiple devices and share processing power for Zero-Knowledge (ZK) verified AI models.

---

## 1. Installation & Launch

### Windows
1. Locate the executable file at: `ui/build/windows/x64/runner/Release/mesh_ui.exe`
2. Double-click the executable to launch the application.
3. Ensure that the associated ONNX dynamic link libraries (`onnxruntime.dll` and `onnxruntime_providers_shared.dll`) are present in the same directory as the `.exe` file.

### iOS
1. Download the `meshnode.ipa` package generated by the GitHub Actions CI pipeline.
2. Sideload the IPA onto your iOS device using a tool like AltStore, Sideloadly, or Apple Configurator.
3. Once installed, tap the **MeshNode** icon on your home screen to launch the application. Note: Ensure you have "Developer Mode" enabled in your iOS settings if required.

---

## 2. Navigating the Dashboard

Upon launching the application, you will be presented with the main Dashboard interface. This interface is divided into several key sections:

### Top Navigation & Telemetry
At the very top, you will see a real-time telemetry overlay providing diagnostic data on your local node's health:
* **RAM (RSS / VSZ):** Shows your current physical and virtual memory utilization.
* **Latency:** Current network latency to the peer network.

### Node Configuration Panel
This section allows you to configure your node's identity and its place in the Ring All-Reduce network.

* **Node ID:** A unique identifier for your device (e.g., `Node-A`).
* **Listen Port:** The local port your node will use to listen for incoming peer connections (default: `50061`).
* **Next Peer Port:** The target port of the next device in the ring topology.
* **Ring Size:** The total expected number of participants in the network.

**Actions:**
* Click the **"Start Node"** button to initialize the libp2p network and begin broadcasting your presence via mDNS.
* Click the **"Connect to Next Peer"** button to actively establish a direct link to the device specified in the "Next Peer Port" field.

### AI Inference & Communication
The chat interface allows you to send text prompts to the local ONNX model and the decentralized network.

1. Type your prompt into the bottom text field (e.g., "Analyze local dataset").
2. Tap the **Send** button.
3. The prompt is processed locally using the quantized 4-bit ONNX model, and the tensor data along with a Zero-Knowledge proof is forwarded to the next peer in the ring for aggregation.
4. The final aggregated result will appear in the chat log.

### FFI Zero-Copy Memory Management
Advanced users can manually interact with the shared memory buffers passing between the Dart UI and the Rust Core:
* **Buffer Size:** Define the size of the shared memory region (in bytes).
* **Allocate Shared Buffer:** Reserves high-speed memory for tensor math.
* **Process Tensor Data (In-Place):** Triggers a Rust simulation of AI activation passes directly on the allocated memory.
* **Free Buffer:** Releases the memory to prevent leaks.

## 3. Network Topology Architecture

MeshNode uses a Ring All-Reduce topology combined with libp2p mDNS discovery. 

```mermaid
graph TD
    A[Node-A (You)] -->|TCP 50062| B[Node-B]
    B -->|TCP 50063| C[Node-C]
    C -->|TCP 50061| A
    
    subgraph Local Device
    A
    end
    
    subgraph Remote Peers
    B
    C
    end
```

When a prompt is sent, the resulting tensor data is passed around the ring. Each node verifies the cryptographic ZK proof attached to the payload before contributing to the computation, ensuring the integrity of the decentralized AI inference.

## 4. Troubleshooting

* **Blank White Screen (iOS) / Crash on Launch (Windows):** This is caused by missing dynamic libraries or an FFI hash mismatch. Ensure the application was compiled with the correct `flutter_rust_bridge` configurations and the ONNX DLLs are in the root directory.
* **Peers Not Discovered:** Ensure all devices are on the same Local Area Network (LAN) and that your firewall allows mDNS UDP broadcast packets.
* **Inference Fails:** Ensure the `minimal.onnx` or `model_4bit_quantized.onnx` files are correctly located in the `assets/models/` directory inside the bundle.
